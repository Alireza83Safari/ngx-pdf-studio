01

چرا این کتابخانه

برای تولید PDF در جاوااسکریپت گزینه کم نیست. تفاوت اینجا در چیزیست که بقیه آخر از همه به آن می‌رسند: متن فارسی که واقعاً درست بچسبد، و خروجی‌ای که فردا هم دقیقاً همان بایت‌های امروز باشد.

jsPDF / pdfmake

سبک و سرراست‌اند، ولی چیدمان راست‌به‌چپ و اتصال حروف فارسی را خودت باید سرِهم کنی، و مفهوم «باند» و صفحه‌بندی گزارشی ندارند.

Puppeteer / HTML → PDF

هر چیزی که مرورگر بلد است را می‌کشد، ولی یک مرورگر کامل را با خودت حمل می‌کنی و خروجی بین نسخه‌های Chrome عوض می‌شود — برای اسناد مالی که باید بایت‌به‌بایت تکرارپذیر باشند، دردسر است.

آنچه اینجا هست

  • فارسی درجه‌یک: bidi استاندارد یونیکد، شکل‌دهی حروف با fontkit، ارقام فارسی و تقویم جلالی — نه به‌عنوان افزونه، بلکه در هستهٔ موتور.
  • پیش‌نمایش دقیقاً همان PDF است: یک درخت لایوت ساخته می‌شود و هر دو نقاش (SVG و PDF) از همان می‌خوانند. اختلاف پیش‌نمایش و خروجی از نظر ساختاری ممکن نیست.
  • خروجی قطعی: دو بار رندر با ورودی یکسان، بایت‌های یکسان می‌دهد — یعنی snapshot test واقعی ممکن است.
  • Expression بدون eval: یک زبان کوچک با lexer و parser اختصاصی و فهرست سفید توابع. قالبِ نااعتماد، دسترسی به میزبان ندارد.

حرف راست

این پکیج هنوز روی npm منتشر نشده و نسخه‌اش 0.0.0 است؛ نصب فعلاً از روی تارball محلی است. دیزاینر بصری هم امروز یک اپ مستقل در همین مخزن است، نه یک کامپوننت Angular آماده — آن فاز بعدی است.

02

مدل ذهنی

کل کتابخانه یک تابع است: قالب و داده می‌گیرد، فهرستی از صفحه‌های چیده‌شده می‌سازد، و آن را یا به SVG می‌کشد یا به PDF. هر چیزی که یاد بگیری، جایی روی این خط می‌نشیند.

PdfTemplateقالب، JSON خالص
→

→
Page[]هندسهٔ نهایی
→
paintToSvg / paintToPdfپیش‌نمایش یا فایل

باند چیست

برخلاف HTML که همه‌چیز در یک جریان می‌ریزد، یک گزارش از نوارهای افقی ساخته می‌شود که هرکدام قانون تکرار خودشان را دارند. این تنها مفهومی است که اگر از دنیای وب می‌آیی باید تازه یاد بگیری — بقیه آشناست.

background پشت همه‌چیز، هر صفحه
watermark مهر یا نوشتهٔ کم‌رنگ روی صفحه
reportHeader فقط یک‌بار، ابتدای سند
pageHeader بالای هر صفحه
columnHeader بالای هر ستون، در چیدمان چندستونی
groupHeader ابتدای هر گروه؛ چندسطحی
detail به ازای هر سطر داده تکرار می‌شود — قلب گزارش
groupFooter پایان هر گروه؛ جای جمع گروه
columnFooter پایین هر ستون
pageFooter پایین هر صفحه؛ شمارهٔ صفحه
reportFooter فقط یک‌بار، انتهای سند

داخل هر باند، المان‌ها با مختصات ثابت می‌نشینند (واحد pt، مبدأ گوشهٔ بالا-چپ). انواع موجود:

staticText dataField richText image table list line rectangle ellipse barcode qrcode chart crosstab subreport pageField container spacer pageBreak formField custom toc

03

نصب

هنوز روی npm نیست

نسخهٔ پکیج 0.0.0 است و هیچ ریلیزی منتشر نشده، پس npm install @ngx-pdf-studio/core شکست می‌خورد. تا اولین تگ v*، از تارball محلی نصب کن.

bash 
npm run build:core                       # compile + prepare core/dist
npm pack packages/pdf-studio/core/dist   # → ngx-pdf-studio-core-0.0.0.tgz

# in your own project:
npm i /path/to/ngx-pdf-studio-core-0.0.0.tgz

حتماً از dist نصب کن، نه از پوشهٔ ورک‌اسپیس

در package.json خودِ پکیج، main به src/index.ts اشاره می‌کند. یعنی اگر با file:packages/pdf-studio/core نصب کنی، تایپ‌اسکریپت خام تحویل مصرف‌کننده می‌شود و بیلد می‌شکند. اسکریپت npm run smoke:tarball دقیقاً همین مسیرِ درست را تست می‌کند.

برای Angular، npm run build را بزن و هر دو تارball را نصب کن — پکیج Angular به core وابسته است.

04

شروع سریع

کوتاه‌ترین مسیر از صفر تا یک PDF فارسی. این کد را کپی کن و اجرا کن — کار می‌کند.

javascript 
const {
  renderToFile,
  loadBundledVazirmatn,
  VAZIRMATN_FAMILY,
} = require('@ngx-pdf-studio/core/node');

const template = {
  schemaVersion: '1.0.0',
  metadata: { name: 'hello' },
  page: {
    size: 'A4',
    orientation: 'portrait',
    margins: { top: 36, right: 36, bottom: 36, left: 36 },
    direction: 'rtl',
    locale: { language: 'fa', digits: 'persian', calendar: 'jalali' },
    unit: 'pt',
  },
  styles: [],
  datasets: [],
  parameters: [],
  bands: [
    {
      id: 'main',
      type: 'reportHeader',
      height: { mode: 'fixed', value: 60 },
      elements: [
        {
          id: 'greeting',
          type: 'dataField',
          bounds: { x: 0, y: 0, width: 300, height: 24 },
          zIndex: 1,
          value: { source: "'سلام، ' + customer.name" },
          typography: { fontFamily: VAZIRMATN_FAMILY, fontSize: 16 },
        },
      ],
    },
  ],
  resources: { fonts: [], images: [] },
};

const result = await renderToFile(
  template,
  { data: { customer: { name: 'علی رضایی' } } },
  'hello.pdf',
  { pdf: { fonts: loadBundledVazirmatn() } },
);

console.log(result.pageCount, result.diagnostics);
typescript 
import { renderToPdf, renderToSvg } from '@ngx-pdf-studio/core';

// In the browser you supply the font bytes yourself — there is no filesystem.
const bytes = new Uint8Array(await (await fetch('/fonts/Vazirmatn-Regular.ttf')).arrayBuffer());

const { bytes: pdf, pageCount, diagnostics } = await renderToPdf(
  template,
  { data },
  { pdf: { fonts: [{ family: 'Vazirmatn', bytes }] } },
);

// Preview instead, without producing a PDF — one SVG string per page.
const { pages } = renderToSvg(template, { data });

رندر برای خطای داده throw نمی‌کند

اگر یک expression بد باشد یا دیتاستی پیدا نشود، نتیجه null می‌شود و یک پیام در diagnostics می‌نشیند. رندر ادامه پیدا می‌کند. همیشه بعد از رندر diagnostics را نگاه کن — بیشتر «چرا این فیلد خالی است؟»ها همان‌جا جواب دارند.

05

گام‌به‌گام: یک فاکتور

حالا از «سلام دنیا» به چیزی که واقعاً تحویل مشتری می‌دهی. هر گام یک تکه به قالب بالا اضافه می‌کند.

  1. دیتاست را اعلام کن

    باندی که قرار است تکرار شود باید بداند روی چه فهرستی می‌چرخد. دیتاست یک‌بار روی قالب اعلام می‌شود و بعد با نام صدا زده می‌شود.

    json 
    "datasets": [
  { "name": "items", "source": { "kind": "path", "path": "items" } }
]

  2. باند detail را بساز

    این باند به ازای هر سطر items یک‌بار کشیده می‌شود. داخلش، نام فیلدها مستقیم در دسترس‌اند و $index شمارهٔ سطر است.

    json 
    {
  "id": "rows",
  "type": "detail",
  "dataset": "items",
  "height": { "mode": "fixed", "value": 18 },
  "elements": [
    { "id": "no",   "type": "dataField", "zIndex": 1,
      "bounds": { "x": 0, "y": 0, "width": 30, "height": 16 },
      "value": { "source": "$index + 1" } },

    { "id": "name", "type": "dataField", "zIndex": 1,
      "bounds": { "x": 40, "y": 0, "width": 200, "height": 16 },
      "value": { "source": "name" } },

    { "id": "sum",  "type": "dataField", "zIndex": 1,
      "bounds": { "x": 250, "y": 0, "width": 100, "height": 16 },
      "value": { "source": "qty * price" },
      "format": { "kind": "currency" } }
  ]
}

  3. جمع کل را در پاورقی بگذار

    در reportFooter دیگر روی یک سطر نیستی، پس با $root به کل داده دسترسی می‌گیری و روی فهرست جمع می‌زنی.

    json 
    { "source": "sum($root.items, qty * price)" }

// «مبلغ به حروف» زیرش:
{ "source": "toWords(sum($root.items, qty * price), 'toman')" }

  4. تاریخ جلالی و شمارهٔ صفحه

    تاریخ با فرمت date کشیده می‌شود و تقویمش را از locale مؤثر می‌گیرد — چون در بالا calendar: 'jalali' گذاشتیم، جلالی درمی‌آید. $page و $pageCount فقط در سر و ته صفحه معنا دارند.

    json 
    { "value": { "source": "now()" },
  "format": { "kind": "date", "dateStyle": "medium" } }

{ "value": { "source": "'صفحهٔ ' + $page + ' از ' + $pageCount" } }

  5. مهر تأیید بزن

    موتور می‌تواند یک مهر تأیید (QR به‌علاوهٔ یک کد کوتاه) روی خروجی بزند که هشِ همان دادهٔ رندرشده را در خود دارد — برای فاکتوری که قرار است بعداً اصالتش بررسی شود.

    javascript 
    await renderToFile(template, { data }, 'invoice.pdf', {
  pdf: { fonts: loadBundledVazirmatn() },
  verify: true,   // or { url: 'https://example.com/verify', label: '…' }
});

06

داده و Expression

هر خاصیتی که تایپش Expression است، شکل { source: '…' } دارد و در زمان رندر ارزیابی می‌شود. زبانش کوچک و عمداً محدود است: نه eval، نه Function، نه دسترسی به میزبان.

ترتیب یافتنِ نام‌ها

یک نام تنها به این ترتیب جست‌وجو می‌شود؛ اولین جایی که پیدا شد، برنده است.

  1. متغیرهای درون‌ساخت — $index، $first، $last، $page، $pageCount، $group، $groupKey، $groupIndex، $vars، $item، $root، $parameters
  2. سطر جاری — فیلدهای همان سطر، از درونی‌ترین به بیرون
  3. پارامترها — آنچه در parameters قالب اعلام شده
  4. دادهٔ ریشه — کلیدهای سطح بالای JSON داده

توابع مجاز

تابع توضیح
sum(list, expr?) expr به ازای هر سطر ارزیابی می‌شود (تنبل): sum(items, qty * price)
avg · min · max همان شکل sum؛ روی فهرست خالی null
count(list) · len(x) len طول رشته را هم می‌دهد
first(list) · last(list) عضو اول / آخر
slice(list, start, end?) برای جمع تجمعی: sum(slice($root.items, 0, $index + 1), amount)
abs(n) · round(n, digits?) کمک‌های عددی
concat(…) · upper(s) · lower(s) رشته؛ + هم به‌هم می‌چسباند
if(cond, then, else) شکل تابعیِ ? :
now() زمان تزریق‌شدهٔ رندر — در تست قطعی است
toWords(n, currency?) مبلغ به حروف فارسی: toWords(4850000, 'rial') → «چهار میلیون و هشتصد و پنجاه هزار ریال»
toPersianDigits(s) · toLatinDigits(s) تبدیل ارقام
formatNumber(n, opts?) · formatCurrency(n, opts?) گروه‌بندی و اعشار بر اساس locale؛ opts.digits: 'persian' | 'latn'

توابع دلخواه هم بدون fork کردن روی رجیستری قابل ثبت‌اند.

متغیرهای گزارش

انباشتگرهای رونده را یک‌بار روی قالب اعلام کن و هرجا با $vars.<name> بخوان.

json 
"variables": [
  { "name": "runningTotal", "expression": { "source": "amount" },
    "calculation": "sum" },

  { "name": "catTotal", "expression": { "source": "amount" },
    "calculation": "sum", "reset": "group", "resetGroupLevel": 0 }
]

calculation: یکی از sum · count · avg · min · max · first · last — و reset یا report (پیش‌فرض) است یا group.

07

فارسی و راست‌به‌چپ

سه چیز جدا از هم‌اند و اغلب با هم قاطی می‌شوند: جهت چیدمان، شکل ارقام، و تقویم. هر سه روی صفحه تنظیم می‌شوند و در باند و المان قابل بازنویسی‌اند.

json 
"page": {
  "direction": "rtl",              // 'ltr' | 'rtl' | 'auto'
  "coordinates": "logical",        // x=0 becomes the start edge, not the left
  "locale": {
    "language": "fa",
    "digits":   "persian",         // 'latn' | 'persian'
    "calendar": "jalali"           // 'gregorian' | 'jalali'
  }
}

مختصات منطقی

به‌طور پیش‌فرض bounds.x فیزیکی است: صفر یعنی لبهٔ چپ کاغذ، هر جهتی که داشته باشی. برای یک سند فارسی یعنی عنوان باید در contentWidth - width بنشیند و هر جفت برچسب/مقدار در سورس برعکس خوانده شود. با coordinates: 'logical' صفر لبهٔ شروع می‌شود و قالب همان‌طور نوشته می‌شود که خوانده می‌شود. روی صفحهٔ چپ‌به‌راست این دو یکی‌اند، پس گذاشتنش بی‌خطر است.

بدون فونت جاسازی‌شده، متن فارسی جعبه می‌شود

فونت‌های استاندارد PDF فقط WinAnsi را می‌شناسند. برای هر متن غیرلاتین باید یک فونت واقعی جاسازی کنی. Vazirmatn داخل خود پکیج هست:

javascript 
// Node — the font ships inside the package (OFL licensed)
const { loadBundledVazirmatn, VAZIRMATN_FAMILY, loadFontFile } =
  require('@ngx-pdf-studio/core/node');

{ pdf: { fonts: loadBundledVazirmatn() } }
{ pdf: { fonts: loadFontFile('./IRANSans.ttf', 'IRANSans', { weight: 400 }) } }

// then point elements (or a named style) at that family:
typography: { fontFamily: VAZIRMATN_FAMILY }

چسبیدن حروف و ترتیب دوجهته با fontkit و پیاده‌سازی استاندارد UAX #9 انجام می‌شود — یعنی جمله‌ای که فارسی و انگلیسی و عدد را قاطی دارد، همان‌طور می‌نشیند که انتظار داری، بی‌آنکه کاری بکنی. برای متن هم‌تراز، typography.align: 'justify' کشیدگی واقعی فارسی (کشیده/tatweel) می‌دهد، نه فاصله‌های کش‌آمده.

08

Angular

سرویس رندر providedIn: 'root' است، پس برای تزریقش هیچ ماژولی لازم نیست. PdfStudioRendererModule فقط وقتی لازم است که کامپوننت پیش‌نمایش را می‌خواهی.

typescript 
import { PdfStudioRenderer } from '@ngx-pdf-studio/angular';

constructor(private renderer: PdfStudioRenderer) {}

async save() {
  // → { bytes, blob, pageCount, diagnostics }
  const result = await this.renderer.render({ template, data });
  this.renderer.download(result, 'invoice.pdf');   // or open() / toObjectUrl()
}

// Preview with no PDF bytes at all — synchronous, one SVG string per page.
preview(): string[] {
  return this.renderer.renderSvg({ template, data }).pages;
}

هر دو متد همان درخواست را می‌گیرند: { template, data?, parameters?, options? }.

کامپوننت پیش‌نمایش

typescript 
import { PdfStudioRendererModule } from '@ngx-pdf-studio/angular';

@NgModule({ imports: [PdfStudioRendererModule] })
export class ReportModule {}
html 
<pdf-studio-preview [template]="template" [data]="data"></pdf-studio-preview>

سازگاری

پکیج منتشرشده Angular ۱۴ تا آخرین نسخه را هدف می‌گیرد و عمداً از Signals، @if/@for، inject() و تحویل standalone-only پرهیز می‌کند. خودِ core هیچ وابستگی‌ای به Angular ندارد.

09

ادیتور اختصاصی خودت

زیر دیزاینر، یک لایهٔ command/store کاملاً فریم‌ورک‌اگنوستیک نشسته که هیچ وابستگی‌ای به Angular یا RxJS ندارد. اگر می‌خواهی ادیتور خودت را با React، Vue یا هرچیز دیگری بسازی، همین کافی است.

typescript 
import {
  DocumentStore, moveElementsBy, groupElements, patchElement,
} from '@ngx-pdf-studio/core';

const store = new DocumentStore(template);

// Fires immediately with the current state, then on every change.
const unsubscribe = store.subscribe((next) => render(next));

store.dispatch(moveElementsBy(['title', 'logo'], 10, 0));
store.dispatch(groupElements(['a', 'b', 'c'], 'group-1'));

store.undo();          // the grouping comes apart exactly as it was
store.getHistory();    // [{ label, type, actor?, at? }, …]
store.undoTo(2);       // jump back to a point in the history

قاعدهٔ طلایی

هرگز درخت قالب را مستقیم دست نزن. state تغییرناپذیر است و هر ویرایش باید از dispatch رد شود؛ وگرنه undo از دستت در می‌رود.

واژگان کامندها

دسته کامندها
المان patchElement setElementBounds moveElementsBy setElementZIndex moveElementZ renameElement setElementLocked addElement removeElementById
گروه‌بندی groupElements ungroupContainer
باند و سکشن patchBand addBand removeBandById moveBand addSection patchSection moveSection removeSectionById
سبک و جزء addStyle updateStyle duplicateStyle removeStyle createSnippet insertSnippet
سند patchPageSetup patchMetadata renameTemplate ensureStyles ensureDataset replaceTemplate

دو نکتهٔ ریز که وقتش را می‌ارزد: کامندهایی که coalesceKey یکسان دارند در تاریخچه یکی می‌شوند — یعنی کل یک درگ، یک قدم undo است. و applyRemote سند را از یک همکار دیگر به‌روز می‌کند بی‌آنکه به تاریخچهٔ undo محلی دست بزند.

عیب‌یابی

متن فارسی به‌جای حروف، جعبه یا علامت سؤال درمی‌آید

فونت جاسازی نشده. فونت‌های استاندارد PDF فقط WinAnsi دارند. در نود loadBundledVazirmatn() را به options.pdf.fonts بده و مطمئن شو typography.fontFamily المان‌ها همان خانواده را نشان می‌دهد.

PDF ساخته می‌شود ولی فیلدها خالی‌اند

diagnostics را چاپ کن. expression بد یا دیتاست پیدانشده باعث null می‌شود و رندر بی‌صدا ادامه می‌دهد. اگر داخل یک باند detail هستی، دقت کن که نام فیلد نسبت به سطر جاری حل می‌شود؛ برای دستِ کل داده باید $root بنویسی.

نصب با file:packages/pdf-studio/core بیلد را می‌شکند

انتظار می‌رود. main آن پوشه به src/index.ts اشاره می‌کند و تایپ‌اسکریپت کامپایل‌نشده تحویل می‌دهد. اول npm run build:core بزن و از packages/pdf-studio/core/dist نصب کن.

خروجی دو بار رندر با هم فرق می‌کند

نباید فرق کند — خروجی قطعی است و همین در تست‌ها بررسی می‌شود. اگر فرق کرد، تقریباً همیشه به‌خاطر now() است که زمان واقعی می‌گیرد؛ زمان را از بیرون به‌عنوان ورودی رندر تزریق کن.

DocumentStore یک قدم اضافه در تاریخچه می‌گذارد

رفتار فعلی همین است: dispatch بی‌قید یک ورودی تاریخچه ثبت می‌کند، حتی اگر کامند در عمل بی‌اثر باشد (مثلاً ensureStyles وقتی سبک از قبل هست). undo هیچ‌وقت چیزی را که از قبل بوده پاک نمی‌کند، ولی قدم خالی در فهرست تاریخچه دیده می‌شود.
